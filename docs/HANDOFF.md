## 1. 새 세션 시작 절차

1. 이 문서를 처음부터 읽는다(특히 2절 규칙, 3절 상태). `git status`, `git log --oneline | head` 로 상태를 확인한다.
2. 개발 서버: `preview_start` 로 `react-dev`(`.claude/launch.json`, `npm run dev`)를 띄운다. 기본 포트는 5173 이지만 **다른 세션의 서버가 쓰고 있으면 5174 처럼 다음 빈 포트가 배정되니**, `preview_start` 결과에 나온 포트로 연다. 다른 세션이 띄운 서버는 꺼질 수도 있다.
3. 화면 확인은 브라우저를 1280×900 으로 맞춘 뒤 한다(8절).
4. 사용자가 "검토만", "검토부터"라고 하면 **코드를 바꾸지 않고** 읽고 판단만 한다. 만들라고 할 때만 만든다.
5. 영역 하나가 끝날 때마다 사용자에게 보여 주고 확인받는다. 커밋은 로컬에 하고, **푸시는 사용자가 "푸시해줘"라고 할 때만** 한다.
6. 푸시한 뒤에는 배포가 끝났는지 확인한다(8-3).

## 2. 사용자 규칙 (반드시 지킬 것)

- 한국어 해요체로 말한다. 결과는 사실대로, 못 한 것·확인 못 한 것은 못 했다고 쓴다.
- **푸시는 사용자가 말할 때만.** 푸시 = Vercel 즉시 배포다. 푸시와 "배포 확인"은 따로 요청받는다.
- 영역별로 만들고 중간에 확인받는다. 결정이 필요한 것은 묻는다.
- **삭제하지 않고 이동(백업)한다.** `rm -rf` 는 자동 심사에서 거부된 적이 있다.
- 브라우저 페이지에서 데이터를 로컬 서버로 보내는 방식(비콘/fetch)은 자동 심사에서 거부된다. 원본 정보는 콘솔에서 읽은 값을 직접 옮겨 적는다.
- 외부에서 받은 파일(이미지 등)은 새 폴더에 넣고 형식을 검사한다. 사용자가 받으라고 한 것만 받는다.
- 코드 규칙: 작은따옴표, 세미콜론 없음, 2칸 들여쓰기, 컴포넌트는 `export default function`, 주석은 코드로 안 드러나는 제약만. 로직 단위는 mm, 3D 장면 단위는 m. 경로 별칭 `@/` = `src/`.
- 이 컴퓨터에는 `pnpm` 이 없다. `npm run dev`, `node node_modules/typescript/bin/tsc -b`, `node node_modules/vite/bin/vite.js build` 를 쓴다.

### 3-6. 색상 선택

선택 카드(새 팝업)와 데모의 선택 카드에 가구별 색상 칩이 뜬다. 고른 색은 `Item.tint`/`tint2` 에 저장돼 해당 3D 모델이 쓴다(`data/furniture.ts` 의 `COLOR_OPTIONS`; 서랍장 제품은 구매 패널 색 10종과 연동). 색 hex 는 이미지로 어림한 값이다.

- **오늘의집에서 실제 색이 확인된 것(3종)**: 심플리 수납장 BC264(옵션 17색 중 재고 15색), 스트링 포켓(색별 상품 10종), 아르덴 미러(화이트·블랙). 오늘의집 상품 옵션은 상품 페이지의 `__NEXT_DATA__` → `props.pageProps.dehydratedState.queries[0].state.data.production.options[].explain` 에서 읽을 수 있다.
- **제가 판단해서 고른 색**: 이불(기본 화이트), 5단 철제선반장, 2인 소파, 스틸 수납 박스, 3단 서랍, 리넨 쿠션(기본 화이트), 철제행거, 다이닝 체어, 모션데스크(상판·다리 5종), 슬라이딩 도어 캐비닛(몸체 5종), 코어렉(선반판 5종). 베이지·그린은 뺐다. `lib/color.ts` 의 `lighten` 이 베개·쿠션 속 같은 밝은 면을 만든다.
- 나머지 가구는 오늘의집에서 같은 상품을 못 찾았거나(FK6720 소파, 룸플러스 러그 등) 색 옵션이 없어서(코어렉은 크기 옵션만) 색을 넣지 않았다. 시몬스 침대는 헤드 색이 다른 모델이 따로 팔린다.

### 3-7. 새 팝업(`FitStudio`, `#/demo2`)

`components/fit/FitStudio.tsx` 하나가 상품 페이지 버튼과 `#/demo2` 를 모두 연다. 옛 팝업은 `?fit=old`. 데이터는 `data/studioLayout.ts`.

**구성**: 머리글(옛 팝업과 같음, 닫기 시 판정 요약을 상품 페이지에 넘김) · 3D 영역(위 막대, 도구줄) · 오른쪽 패널(선택 카드 + 탭 3개 + 공간 적합도 진단). 탭은 **내 공간 치수**(가로·세로·천장 높이·방문 폭, 1~10000mm) / **통합**(배치된 가구·상품 종류 토글; 같은 상품은 한 줄 ×개수, ＋/−/X, 문·창문 줄, 창문 0~4개) / **직접 입력**(흐림 + "Coming Soon…"). 하단 도구: 90° 회전(R), 벽에 붙이기, 서랍 열어보기(서랍장·3단 서랍을 골랐을 때만), 위에서 보기, 초기화(가구 배치와 방 치수 4.5×4.5m 복원, 창문 개수는 유지). 3D 를 그리는 동안(화면이 바뀔 때마다) 스피너를 먼저 보여 준다.

**판정(`lib/fit.ts`)**: 서랍장 제품은 `evaluate`(옛 팝업과 같은 기준), 나머지는 `measureFurniture`. 새 화면의 진단은 고른 가구 기준이고 항상 보인다(직접 입력 탭 제외). 가구 53종을 하나씩 눌러 본 결과 빨강·노랑 없이 전부 "배치 가능"이고, 침대 머리·3단 서랍·책상·모니터암에 "벽에 붙이기"를 써도 그렇다(점검 방법은 8-2). 규칙: 높이가 150mm(얇은 물건은 절반) 넘게 겹쳐야 서로 막음 / 의자는 책상·테이블 아래와 상판 위 물건 밑으로 들어감 / 블라인드에 100mm 이하로 걸친 것은 통과 / 같은 걸이 물건끼리 겹쳐도 됨 / 러그는 문 열림에서 뺌 / 방 밖 판정은 5mm 여유 / 앞쪽 여유 60cm 는 바닥에 선 큰 가구만(의자·침대 발치 제외), 앞 장애물에서 의자·문 열림 자리·소파 앞 테이블·행거 앞 벽 수납장 제외 / 창가 커튼 라인(창에서 200mm)은 창턱(1300mm)보다 낮은 가구에는 적용 안 함(`Rect.bottom`) / `backToWall` 은 d 의 절반을 쓰고(옛 팝업 서랍장에도 적용됨) 두 벽에 똑같이 가까우면 지금 향한 벽을 고른다.

- 리뷰/문의 2~9쪽은 원본 API(CORS 로 막힘)에서 옮긴 정적 데이터라 시간이 지나면 원본과 달라진다. 리뷰의 정렬·별점·옵션 필터는 옮겨 둔 45개 안에서만 동작한다(원본은 15,000개 이상). 옵션 목록은 45개에 나온 11개뿐이다. 1~2점 리뷰는 없다.

- 도움돼요 아이콘은 원본 Lottie 정지 프레임과 눌렀을 때 채워진 모양만 옮겼다(퍼지는 선 애니메이션 없음).

- 3D 팝업에서 책상 상세 뷰 진입/복귀 시 콘솔에 `removeChild` 에러가 난다(drei `Html` + StrictMode). 원본 코드에서도 나는 기존 이슈이고 화면은 정상이다. 데모에서는 `Attempted to synchronously unmount a root...` 가 보일 수 있다(같은 계열).
- 데모: 추가한 가구는 새로고침하면 사라진다. 상품 종류 57개는 모두 3D 모델이 있고(이미지로 추정한 모양), 직접 입력한 가구만 치수 상자로 보인다. 걸리는 가구(거울·액자·블라인드·TV 등)는 `elevation` 높이로 걸리지만 새로 놓으면 방 가운데에 걸리므로 "벽에 붙이기"로 맞춘다. 가구 분류(가구/소품/벽·천장)는 사람이 나눈 것이다.
- 싱글 모니터암은 원본 치수가 전부 0이라 `data/furniture.ts` 의 `ESTIMATED_SIZE` 로 W120×D480×H400mm 를 추정해 넣었고, 책상 위(720mm)에 얹도록 `elevation` 을 줬다. 실제 제품 치수를 알면 그 값으로 바꾼다.

### 7-1. 오늘의집 상품 페이지 (`#/`)

- **헤더 스크롤**(`SiteHeader.tsx` 의 `useHeaderMode`): 100px 이상 내리면 상단 줄만 `fixed`(탭 바 top 80, 카드 134), 위로 올리면 카테고리 줄도 내려옴(탭 바 132, 카드 186, 높이 714). 탭을 눌러 이동할 때는 `pin()` 으로 잠깐 상단 줄만 유지해 제목이 가려지지 않게 한다. 상수는 `StickyTabs.tsx` 의 `TAB_TOP_*`.

"동작 줄이기" 설정에서는 멈춘다.
- 리뷰·문의: 쪽 번호가 1~9쪽 모두 바뀌고, 쪽을 바꾸면 영역 제목이 154px 에 온다.

### 7-2. 옛 3D 팝업 "내 공간에 맞는지 확인하기" (`FitModal`, `?fit=old` — 새 팝업이 이 기능을 이어받았다. 바꿀 때 그대로인지 확인한다)

진입: 대표 이미지 오른쪽 아래 버튼 → `FitModal`(`React.lazy`, z-index 2000). 색상은 구매 패널에서 마지막으로 고른 색을 따른다.

- **방**: 기본 `6000×6000mm`, 천장 2600, 문 900. 프리셋은 "넓은 침실 · 책상 아래" 하나. 기본 가구는 `catalog.ts` 의 `wideFurniture`(침대·책장·소파·화분·책상·의자 + 러그 2개). 방이 `3800×3600`보다 작으면 옛 3종 배치(`isWideRoom` in `room.ts`).
- **시점**: 아이소메트릭에 가까운 좁은 화각(fov 24°), 앞쪽 벽(-x, +z)은 카메라가 바깥에 있으면 거의 투명. 마루판 바닥 / 흰 타일 벽 / 창 / 벽 조명·선반.
- **도구**: 오른쪽 위 확장/축소 버튼, 하단 툴바 `90° 회전 · 벽에 붙이기 · 서랍 열어보기 · 위에서 보기 · 초기화`, 하단 안내 "실측 규격 W×D×H | 서랍 앞 여유".
- **오른쪽 패널**: 탭(방 화면: `내 공간 치수 / 함께 둔 가구 / 색상`, 상세 화면: `내 책상 치수 / 서랍장 위치·바퀴 / 색상`) + 항상 보이는 "공간 적합도 진단".
- **문구**: 제목 "내 공간에 맞는지 확인하기", 안내는 방 전체 보기 "방을 둘러보고, 가구를 배치해 보세요." / 책상·서랍장 상세 보기 "책상 치수와 서랍장 위치를 조정하고, 설치 조건을 확인해 보세요." 판정 제목은 "입력한 치수 기준으로 배치 가능해요" / "현재 배치에서는 사용 공간이 부족해요".
- **상세 뷰**(책상 클릭 또는 "책상·서랍장 치수 자세히 입력하기"): 책상 기준 360° 뷰, 치수선(mm), 서랍장 위치 입력, 바퀴 on/off + 바퀴 높이(20~100mm, 기본 30). "내 책상 치수" 탭은 설치 공간 치수(상판 아래 높이·다리 안쪽 폭) + 접을 수 있는 책상 전체 크기 + 치수 입력 안내 구성이다.
- **제품 규격**: 가로 280 × 세로 410 × 높이 685mm(바퀴 30mm 포함, 본체 655). 진단 문구의 높이는 68.5cm 처럼 소수 한 자리까지 보인다(`fit.ts` 의 `cmH`).
- **판정 기준**(`lib/fit.ts` `evaluate`): 방 밖/천장 초과 불가, 겹침 불가(단 책상 아래 높이 ≥ 제품 높이면 "아래에 들어감"), 책상 다리 겹침 불가, 위 여유 20mm 미만 주의, 서랍 앞 350mm 미만 불가·600mm 미만 주의, 옆 간격 0~20mm 주의, 문 열림 반경 침범 불가, 창가 커튼 200mm 주의.
- 좌표: x = 0..방 가로(왼쪽 벽에 문, 오른쪽 벽에 창), z = 0..방 세로(z=0이 뒷벽). `Item.rot` 0~3(90° 단위). 책상 기준 좌표는 `lib/desk.ts`.

### 7-4. 코드로 만든 3D 가구 모델 (`#/models`, `ArchiModels.tsx`, `Models.tsx`)

- 기존 가구(침대, 책상, 소파 등)와 같이 **모델 파일(GLB 등)이 아니라 Three.js 기본 도형을 코드로 조합**한 React 컴포넌트다. 기준: 가구 가운데 바닥이 `(0,0,0)`, 앞이 `+z`, 높이가 `+y`, 단위 m(`item.h / 1000`). 치수(`w, d, h`)를 받아 그 크기에 맞춰 계산한다. 벽에 거는 가구는 뒷면이 `-z`(벽 쪽)다.
- `ArchiProps.tsx` 에 작은 가구·소품·벽 가구 모델 48종(50개 가구, 책 3종은 `bookrow` 공유)이 `PROP_MODELS` 표로 들어 있다(`Models.tsx` 의 `default` 가 이 표를 본다). 새 소품은 여기에 컴포넌트를 더하고 `lib/types.ts` 의 `PropModel` 에 이름을 넣으면 된다.
- 앞의 16개: 소파 `fksofa`, 데스커 의자 `meshchair`, 다이닝 의자 `diningchair`, 모션데스크 `motiondesk`, SIMPLIE 수납장 `chromecabinet`, 코어렉 `corerack`, 아랄리아 화분 `aralia`, 3단 서랍 `drawerunit`, QLED 벽걸이 TV `walltv`(걸림 900mm)(모두 `ArchiModels.tsx` 아래쪽, 모양은 이미지로 추정)와 처음 6개: W1000 원형테이블 `roundtable`(`Models.tsx`), D2178B 침대 `bedframe`, H1740 철제선반장 `steelshelf`, perforated board `pegboard`(걸림 1100mm), 아르덴 미러 `mirror`(900mm), 우드 블라인드 `blind`(240mm) (`ArchiModels.tsx`).
- **침대 + 침구 한 덩어리**: D2178B 침대는 `bedset` 모델(`ArchiModels.tsx` 의 `BedWithBedding` = 검은 프레임·헤드보드·흰 매트리스 + 그 위에 덮인 푸른 이불·베개 3개)이라 침구와 하나로 움직인다. 크기는 침대(프레임) 기준 1125×2098×1058mm 이고 이불은 프레임보다 조금 넓게 덮는다. Villette Blue 침구(`Ydpb3l75…`)는 `data/furniture.ts` 의 `BUNDLE_OF` 로 침대에 묶여, 전체 가구에서 그 카드를 눌러도 침대 세트가 놓인다(카드에 "침대에 포함돼요" 표시). 플래너 배치(`plannerLayout.ts`)에서도 침구 줄을 지우고 침대 이름에 ` + 침구`를 붙였다. 침구만 따로 보여 주는 `bedding` 모델(`ArchiProps.tsx`)과 이불 없는 `bedframe` 모델은 `#/models` 용으로 남아 있다.
- **새 모델 추가 절차**: ① `lib/types.ts` 의 `ItemModel` 에 이름 추가 → ② `ArchiModels.tsx` 에 컴포넌트 작성(원본 이미지는 `public/archisketch/{componentId}.png`) → ③ `Models.tsx` 의 `switch` 에 `case` 추가 → ④ `data/furniture.ts` 의 `MODEL_BY_FURNITURE` 에 `{ model, elevation? }` 등록(키는 componentId) → ⑤ `#/models` 에서 원본 이미지와 비교하며 확인 → ⑥ `#/demo` 에서 놓아 본다. 등록하지 않은 가구는 치수 상자(`box`)로 보인다.
- 이미지만으로는 뒷모습·옆모습을 알 수 없어서 세부(손잡이, 다리 꺾임, 슬랫 각도 등)는 추정이다. 실제 제품과 똑같이 하려면 3D 모델 파일(GLB)이 필요하다(지금 구조에는 파일을 불러오는 기능이 없다. `useGLTF` 로 불러와 `w,d,h` 에 맞춰 크기를 조정하는 컴포넌트를 새로 만들어야 한다).
- 3D 변환용 이미지를 다른 AI 에게 요청할 때는 흰 배경, 그림자 없음, 원근 없는 정면·측면·위에서 본 3면도, 치수(W·D·H) 글 표기가 가장 변환하기 쉽다.

## 8. 검증 방법

### 8-1. 원본 오늘의집 페이지와 비교할 때

- 원본 탭과 우리 탭 모두 **뷰포트 1280×900** 으로 맞춘다(`resize_window`). 탭을 바꾸면 에뮬레이션이 풀리므로 매번 다시 맞춘다. 맞추지 않으면 원본이 모바일 레이아웃(쪽 번호 5개 등)으로 열린다.
- 같은 문구를 가진 요소의 `getBoundingClientRect()` 위치·크기·글자 크기를 양쪽에서 읽어 비교한다(1px 이내). 원본 내용은 시간이 지나면 바뀌므로(리뷰 날짜, 인기 검색어 등) 위치는 "섹션 내부 상대 좌표"로 본다.
- 스크롤 동작은 코드로 `scrollTo` 점프하지 말고 **실제 휠 스크롤**(`computer` 도구의 `scroll`, 1칸 = 100px, 한 번에 최대 10칸)로 테스트한다. 점프하면 헤더 상태가 달라져 착시가 생긴다.
- `loading="lazy"` 이미지는 화면 근처에 와야 불러온다. 이미지당 5초 이상 기다려 확인한다. 상세 이미지 9장은 배포 환경에서 모두 불러와지는 것을 확인했다.
- 원본 기준 좌표(1280×900, 스크롤 0): 헤더 상단 줄 50~131, 카테고리 줄 131~183, 히어로 261, 탭 바 1400(높이 54), 본문 시작 1534, 스타일링샷 640px, "함께 둘러보면 좋아요" 2254(451px), 상품정보 2785. 스크롤 후 원본: 100px 내리면 상단 줄 고정(탭 바 80·카드 134), 위로 올리면 탭 바 132·카드 186(높이 714).
- 원본의 리뷰·문의·추천 데이터는 `store.ohou.se/api/goods/reviews`, `/api/goods/questions`, `/api/goods/307306/recommended` 에서 읽을 수 있다(원본 탭 안에서만 호출되고 다른 도메인에서는 CORS 로 막힌다).

### 8-2. 화면·3D 확인할 때 (이번에 겪은 것)

- 브라우저 패널이 숨겨져 있으면 **3D 캔버스가 처음엔 비어 보이고**(몇 초 뒤 그려짐), **CSS 애니메이션 시간이 멈춘다**. 스크린샷을 한 번 찍으면 다시 흐른다. 애니메이션은 계산된 값(`getComputedStyle`)을 여러 번 읽어 확인한다.
- 개발 서버 화면이 수정 직후 이전 상태로 보이면 쿼리를 바꿔(`/?v=2#/demo`) 다시 연다.
- 3D 를 가까이 보려면 캔버스에 `WheelEvent` 를 보내거나 휠로 확대하고, 가구를 하나씩 돌려 보려면 `#/models` 를 쓴다.
- 개발 서버 포트가 5173 이 아닐 수 있다(1절). 앱 안 브라우저에서 `localhost:<포트>` 로 연다.
- Archisketch 플래너 같은 외부 로그인 사이트는 앱 안 브라우저의 기존 로그인 상태를 읽기만 하고, 로그인 정보를 입력하거나 편집·저장하지 않는다(7-3 의 읽는 방법).
- 3D 확인: 가구를 놓은 뒤 선택 카드의 크기·여유·판정 문구를 읽고, 스크린샷으로 모양을 본다. 기존 팝업이 그대로인지(탭 3개, 진단 문구, 규격)도 함께 본다.

- **새 팝업 진단 일괄 점검**: `#/demo2` 를 1280×900 으로 열고 `통합` 탭의 가구 줄을 하나씩 눌러 가며 `공간 적합도 진단` 영역 글자를 읽어 빨강("사용 공간이 부족")·노랑("확인이 필요")이 있는지 센다(javascript_tool 로 한 번에 돌릴 수 있다). 그리고 침대·3단 수납형 서랍·모션데스크·싱글 모니터암을 골라 "벽에 붙이기"를 누른 뒤에도 통과하는지 본다(매번 "초기화"로 되돌리고).
- 상세 보기는 위에서 보기로 바꾸고 가구 위를 눌러 "제품 상세 페이지 이동" 버튼이 뜨는지 확인한다. 책상 위에는 물건이 많아 책상 가장자리를 눌러야 책상이 골라진다.

### 8-3. 푸시 후 배포 확인

1. `git push origin main`.
2. `gh api repos/chahyun-dot/1/commits/<sha>/status` 에서 `Vercel` 상태가 `Deployment has completed`(success)가 될 때까지 기다린다(보통 20초~3분).
3. `curl -s https://roomjirak.vercel.app/ | grep -o 'index-[A-Za-z0-9_-]*\.js'` 로 번들 이름이 바뀌었는지 본다(문서만 바뀐 푸시는 번들이 그대로여서 정상이다).
4. 배포본을 1280×900 으로 열어 바뀐 기능을 직접 확인한다. 응답 코드가 404(`DEPLOYMENT_NOT_FOUND`)이면 도메인 연결 문제다(Vercel 대시보드에서 도메인 확인을 사용자에게 부탁한다).
